# og-ticket Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mod that keeps the project's work item in focus (optional ID + description), set with `/og-ticket` or by Claude through `og_ticket_set`, and shows it on the status line.

**Architecture:** `hooks/focus.ts` holds the pure parsing and status text; `hooks/register.tsx` wires `session.start`, the command, the tool and `$.store`. Same idioms and test harness as `mods/og-sf-org-status`.

**Tech Stack:** Claude Code hooks API, TypeScript, `claude plugin validate` / `claude plugin test`, `scripts/check.sh`.

**Spec:** `docs/specs/2026-10-14-og-ticket-design.md`

## Global Constraints

- Mod `og-ticket` in `mods/og-ticket/`, command `/og-ticket`, tool `og_ticket_set` (`mcp__og-ticket__og_ticket_set`), version `0.1.0`.
- ID regex `[A-Z][A-Z0-9]+-\d+`; status `🎫 <ID> · <description>` or `🎫 <description>`, cut to 60 chars with `…`.
- Store key `project:<git root or cwd>`. English in code, docs and commits.

## Review Focus

1. Not a git repo / `git` missing → the cwd is the project, no error.
2. `/og-ticket sfcomprg-1234 x` (lowercase) → not an ID; the whole text is the description.
3. A one-word ID with no description (`/og-ticket PLA-41`) → ID alone, line `🎫 PLA-41`.
4. `og_ticket_set` with an empty description and no ID → refused, nothing stored.
5. Multi-line or padded text → collapsed to one line, trimmed.
